**Дисциплина:** Защита информации в операционных системах  
**Тема:** Протокол SSH. Защита удалённого подключения  
**Среда:** Debian 12 (Bookworm)  
**Продолжительность:** 2 академических часа (90 минут)

## Цель работы

Изучить протокол SSH, освоить методы повышения защищённости SSH-сервера, научиться настраивать аутентификацию по ключам, ограничивать доступ, использовать нестандартные порты, а также подключаться к серверу из различных сетевых окружений (локальная сеть, туннель, проброс портов).

**Формат работы:** каждое действие — одна команда. Вводите команды по порядку, фиксируйте результат в отчёт.

---

## Теоретическая справка

**SSH (Secure Shell)** — сетевой протокол прикладного уровня для безопасного удалённого доступа к системам. Обеспечивает шифрование трафика, аутентификацию сторон и целостность данных. Основные компоненты:

- **ssh** — клиент;
- **sshd** — сервер;
- **ssh-keygen** — генерация ключей;
- **ssh-copy-id** — копирование открытого ключа на сервер;
- **ssh-agent** — агент для хранения ключей.

Основные методы аутентификации: по паролю, по ключу (публичный/приватный), по сертификату, по одноразовым паролям (OTP).

Для фильтрации трафика используется `iptables` — классический инструмент управления правилами межсетевого экрана в Linux.

## ЭТАП 3. Аутентификация по ключам

### Шаг 3.1. Генерация пары ключей на Client

Выполните на **Client** (под пользователем `debian`, не `root`):

```bash

```

```bash
ssh-keygen -t ed25519 -a 100 -f ~/.ssh/id_ed25519_lab -C "lab-key-$(date +%F)"
```

**Ожидаемый результат:** запрос пароля для ключа. **Введите пароль** (например, `keypass`) или оставьте пустым.

- `-t ed25519` — современный алгоритм, стойкий и быстрый;
- `-a 100` — 100 раундов KDF (замедляет подбор пароля);
- `-f` — путь к файлу ключа;
- `-C` — комментарий.

Проверьте:

```bash
ls -la ~/.ssh/
```

**Ожидаемый результат:** файлы `id_ed25519_lab` (приватный, права `600`) и `id_ed25519_lab.pub` (публичный, права `644`).

**Зафиксируйте вывод в отчёт.**

### Шаг 4.2. Создание отдельного файла конфигурации

Создайте файл `/etc/ssh/sshd_config.d/99-hardening.conf`:

```bash
nano /etc/ssh/sshd_config.d/99-hardening.conf
```

Вставьте текст:

```
# Запретить вход root напрямую
PermitRootLogin no

# Запретить аутентификацию по паролю
PasswordAuthentication no
PermitEmptyPasswords no
KbdInteractiveAuthentication no
ChallengeResponseAuthentication no

# Разрешить вход только пользователю debian
AllowUsers debian

# Отключить X11-форвардинг
X11Forwarding no

# Ограничение попыток аутентификации
MaxAuthTries 3
MaxSessions 2
LoginGraceTime 30

# Тайм-аут неактивной сессии
ClientAliveInterval 300
ClientAliveCountMax 2

# Использовать только протокол SSH-2
Protocol 2

# Запретить использование .rhosts
IgnoreRhosts yes
HostbasedAuthentication no

# Приветственное сообщение
Banner /etc/ssh/banner
```

Сохраните (`Ctrl+O`, `Enter`, `Ctrl+X`).

## ЭТАП 5. Смена порта и ограничение доступа через iptables

### Шаг 5.1. Смена стандартного порта (на Server)

```bash
nano /etc/ssh/sshd_config.d/99-hardening.conf
```

Добавьте в конец файла:

```
Port 2222
```

Сохраните (`Ctrl+O`, `Enter`, `Ctrl+X`).

---

### Шаг 5.2. Настройка iptables

Выполните на **Server**:

```bash
iptables -F
iptables -X
iptables -P INPUT DROP
iptables -P FORWARD DROP
iptables -P OUTPUT ACCEPT
```

**Пояснение:**
- `-F` — очистить все правила;
- `-X` — удалить пользовательские цепочки;
- `-P INPUT DROP` — по умолчанию входящий трафик запрещён;
- `-P OUTPUT ACCEPT` — исходящий трафик разрешён.

**ВНИМАНИЕ!** Если вы работаете через SSH-сессию, до применения политики `DROP` убедитесь, что правила `ACCEPT` для SSH будут добавлены первыми. Ниже — безопасный порядок команд.

Разрешите loopback-интерфейс:

```bash
iptables -A INPUT -i lo -j ACCEPT
```

Разрешите уже установленные соединения:

```bash
iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT
```

Разрешите SSH на новом порту только с IP-адреса Client:

```bash
iptables -A INPUT -p tcp -s $CLIENT_IP --dport 2222 -j ACCEPT
```

Разрешите ICMP (ping):

```bash
iptables -A INPUT -p icmp --icmp-type echo-request -j ACCEPT
```

**Ожидаемый результат:** команды выполнены без ошибок.

Проверьте правила:

```bash
iptables -L -n -v --line-numbers
```

**Ожидаемый результат:** таблица с правилами, где политика `INPUT` — `DROP`, а правила `ACCEPT` — для `lo`, `ESTABLISHED,RELATED`, SSH на 2222 и ICMP.

**Зафиксируйте вывод в отчёт.**

### Шаг 5.6. Проверка ограничения по IP

### Шаг 5.7. Просмотр заблокированных пакетов (опционально)

Добавьте логирование заблокированных пакетов перед политикой `DROP`:

```bash

```

**Ожидаемый результат:** `Connection refused` или тайм-аут.

Посмотрите журнал на Server:


**Ожидаемый результат:** строки вида `SSH_BLOCKED: IN=... SRC=... DST=... DPT=22`.

## ЭТАП 6. Подключение из различных сетевых окружений

### Шаг 6.1. Использование SSH-туннеля (локальный проброс портов)

На **Client** выполните:

```bash
ssh -p 2222 -i ~/.ssh/id_ed25519_lab -L 8080:localhost:80 debian@$SERVER_IP -N &
```

**Пояснение:** локальный порт `8080` на Client перенаправляется на порт `80` на Server. Ключ `-N` означает «не выполнять команды», `&` — запуск в фоне.

Проверьте:

```bash
ss -tlnp | grep 8080
```

**Ожидаемый результат:** строка с `LISTEN` на порту `8080`.

**Зафиксируйте вывод в отчёт.**

Остановите туннель:

```bash
kill %1
```

---

### Шаг 6.2. Динамический проброс (SOCKS-прокси)

На **Client** выполните:

```bash
ssh -p 2222 -i ~/.ssh/id_ed25519_lab -D 1080 debian@$SERVER_IP -N &
```

**Пояснение:** на Client открывается SOCKS5-прокси на порту `1080`. Все запросы через него идут через Server.

Проверьте:

```bash
ss -tlnp | grep 1080
```

**Ожидаемый результат:** `LISTEN` на `1080`.

Остановите:

```bash
kill %1
```

---

### Шаг 6.3. Обратный проброс портов (remote forwarding)

На **Client** выполните:

```bash
ssh -p 2222 -i ~/.ssh/id_ed25519_lab -R 9090:localhost:22 debian@$SERVER_IP -N &
```

**Пояснение:** порт `9090` на Server перенаправляется на порт `22` на Client. Это позволяет Server подключаться к Client через SSH.

На **Server** проверьте:

```bash
ss -tlnp | grep 9090
```

**Ожидаемый результат:** `LISTEN` на `9090`.

Теперь с Server можно подключиться к Client:

```bash
ssh -p 9090 debian@localhost
```

**Ожидаемый результат:** подключение к Client (запрос пароля ключа или пользователя).

Выйдите:

```bash
exit
```

На **Client** остановите туннель:

```bash
kill %1
```

---

### Шаг 6.4. Подключение через jump host (ProxyJump)

На **Client** создайте файл `~/.ssh/config`:

```bash
nano ~/.ssh/config
```

Вставьте текст (замените IP-адреса на свои):

```
Host jump
    HostName 192.168.56.10
    User debian
    Port 2222
    IdentityFile ~/.ssh/id_ed25519_lab

Host target
    HostName 192.168.56.20
    User debian
    Port 2222
    IdentityFile ~/.ssh/id_ed25519_lab
    ProxyJump jump
```

Сохраните (`Ctrl+O`, `Enter`, `Ctrl+X`).

Установите права:

```bash
chmod 600 ~/.ssh/config
```

Подключение через jump host:

```bash
ssh target
```

**Ожидаемый результат:** подключение к Server через Client как промежуточный хост.

Выйдите:

```bash
exit
```

**Зафиксируйте вывод в отчёт.**

---

### Шаг 6.5. Подключение из «внешней» сети (эмуляция)

Смена порта и ограничение по IP через `iptables` уже эмулируют подключение из разных окружений. Дополнительно проверьте подключение с использованием IPv6, если он настроен:

**Ожидаемый результат:** либо успешное подключение, либо `Network is unreachable` (если IPv6 не настроен).
